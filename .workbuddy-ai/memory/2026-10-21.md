## 首页预约卡片：区分「取消预约」与「停止使用」

- 根因：履约中（已刷通道机签到）的预约，官方只有 `make/stop` 才能释放座位，原来卡片一律显示「取消预约」调 `make/cancel`，对已签到记录无效/报错。
- 改动：`ReservationCard` 按状态分流 —— 待签到（RESERVE/BOOKED/RESERVED）→「取消预约」；履约中/暂离（IN_USE/USING/CHECKED_IN/CHECK_IN/ACTIVE/AWAY/LEAVE）→「停止使用」（`PowerSettingsNew` 图标）+ 二次确认 `AlertDialog`。
- `HomeViewModel` 新增 `stoppingReservation` 状态与 `stopReservation(id)`，走 `repo.stopUsage` → `POST /static/frontApi/make/stop`（检查 `data.status`），成功后 `refreshReservation()` + snackbar；按钮期间显示 16dp `CircularProgressIndicator`。
- 状态标签补齐别名映射：`CHECK_IN` 归入「履约中」、`RESERVED` 归入「待签到」，避免显示原始英文状态。
- 与 `SeatMapScreen` 的「提前结束」逻辑保持一致（同一接口）。

## 首页常用座位卡片：等高对齐

- 问题：卡片内容不定长（无使用统计、无「靠窗/有电源」标签）导致同行卡片高度/宽度参差。
- 处理：统计行恒显示（无数据时显示灰色「近一年暂无预约记录」）；座位名与统计行 `maxLines=1` + `TextOverflow.Ellipsis`；无任何标签时用 `Box(Modifier.alpha(0f)) { Tag("靠窗") }` 透明占位补齐高度。

## 应用图标换成三椅设计图（adaptive icon）

- 原图标是 `res/drawable/ic_launcher.xml` 单文件矢量（深绿底 + 白书 + 粉点），manifest 直接指向 drawable，Android 8+ 会被启动器套白底容器。
- 新方案：标准 adaptive icon。`mipmap-anydpi-v26/ic_launcher(.xml/_round.xml)` = `<background @color/ic_launcher_background>` + `<foreground @mipmap/ic_launcher_foreground>`；各密度（m/h/xh/xxh/xxxh）另出 `ic_launcher.png`（圆角 22%）与 `ic_launcher_round.png`（正圆）作为非 adaptive 兜底。
- 前景图由设计图裁出图形带（原图 1254²，内容 bbox 112,494→1142,760）后居中合成到 108dp 画布，**图形宽度占 68%**：62% 时在圆形遮罩里显小，70%+ 会把两侧扶手圆头裁平。前景保持不透明（填同色背景），避免抠图暗边，背景层同色所以无缝。
- 取色：背景 `#016448`，白椅 `#F8F8F8`，中间椅 `#B0F8D0`。
- 关键坑：**不能给 adaptive icon 加 `<monochrome>` 指向这张不透明前景图** —— 系统按 alpha 通道做单色渲染，全不透明会变成一整块纯色方块。已移除。
- manifest 改 `@mipmap/ic_launcher` / `@mipmap/ic_launcher_round`，删除旧 `drawable/ic_launcher.xml`。
- 签名未动：`build.gradle.kts` 无自定义 signingConfig，仍是默认 debug keystore；`apksigner verify --print-certs` 确认 `CN=Android Debug`，SHA-256 `a0246444d59f4193124fb222f3432caba301b8b5b5040a8448f405720be03eca`。
- 注意：覆盖安装后桌面图标可能仍是旧缓存，需卸载重装或重启启动器。

## 图标换第二版设计图

- 用户第二次提供的是同构图的「紧凑版」：图形 bbox 只有 638×174（原 1030×266），即椅子更小、间距更紧；背景色略深 `#02664C`（原 `#016448`）。
- 生成流程已固化为一次性脚本（用完即删，不入库）：采样背景色 → 阈值求非背景 bbox → 裁图形带 → 按 `CONTENT_RATIO` 缩放居中合成到 108dp 画布（前景不透明、填同色底）→ 输出 5 个密度的 foreground/legacy/round PNG + 更新 `values/ic_launcher_background.xml`。
- `CONTENT_RATIO` 取 0.68 是实测平衡点：圆形遮罩（可见直径 72dp）下 0.70+ 会削平两侧扶手圆头，0.62 又显得偏小。
- 构图按 bbox 中心对齐画布中心，顺带修正原图 8px 的垂直偏移。
- 用户反馈「偏大」，要求图形缩小一倍：`CONTENT_RATIO` 0.68 → **0.34**（legacy PNG 同步按比例降到 0.41）。此比例下 72dp 可见圆内图形仅占一半宽，48dp 桌面图标时图形约 16×4.4dp，细节会明显糊；若要回调，0.45~0.50 是辨识度与留白的平衡点。
- 再回调放大 1.25 倍：0.34 × 1.25 = **0.425**（legacy 0.512），当前生效值。结论：图标图形占比的可用区间大致 0.40~0.68，低于 0.40 小尺寸不可辨、高于 0.70 圆遮罩削扶手。
