# 复用与改动说明

本文说明对 `whu-ham/whu-ham.github.io` 的调研结论、复用范围、改动边界，以及新增功能（默认图书馆 / 默认楼层 / 常用座位 / 一键预约 / WebView 登录）的实现结构。

## 1. 调研结论

`whu-ham/whu-ham.github.io` 是 Ham 的 **VitePress 文档站**，不是 App 源码仓库。全仓库与图书馆相关的只有三份使用手册：

- `docs/src/guide/handbook/library.md`
- `docs/src/en/guide/handbook/library.md`
- `docs/src/ja/guide/handbook/library.md`

同组织的 `ham-rn`（React Native 组件）、`ham-web`（Web 登录）、`ham-open-proto`（开放平台 proto）中也没有图书馆模块的实现代码。因此不存在“直接拷贝代码”的复用，本项目复用的是：

1. **文档描述的预约业务逻辑**；
2. **Ham 对接的座位系统接口约定**（seat.lib.whu.edu.cn 的 `/rest` 系列端点）。

### 复用的业务逻辑

| Ham 文档中的行为 | 本项目对应实现 | 改动 |
| --- | --- | --- |
| 看板预约：按图书馆 / 房间 / 座位查看余量并直接预约 | `SeatMapScreen` + `WhuLibraryApi.seatMap/book` | 重写为 Compose 座位网格；新增收藏、时间选择 |
| 快速预约：使用“首选座位”直接下单 | `QuickBookUseCase` | 从单一首选座位扩展为“多常用座位” |
| 首选座位失败后立刻选附近座位 | `QuickBookUseCase.buildCandidates` | 保留同区域最近空座回退，增加 350ms 请求间隔与尝试上限 |
| 首选座位可预设时间 | 默认时间段（设置页） | 全局时间段 + 首页一键预约 |
| 预约状态展示、改时间、取消 | 首页预约卡、`/rest/v2/cancel/{id}` | 新增取消确认与状态刷新 |
| 历史记录 | `/rest/v2/history/{page}/{count}` | 设置页展示最近 5 条 |
| 基础数据本地缓存、进入页面时更新 | `CatalogSnapshot` + DataStore（24h） | 原生缓存 + 手动刷新 / 清除 |
| 通过信息门户 / 读者证号登录 | **WebView 登录页 + token 捕获** | 由原生表单改为网页登录，见第 4 节 |

### 复用的接口

经典座位系统的接口约定（Ham 文档与公开资料一致）：

| 能力 | 接口 |
| --- | --- |
| 登录 | `POST/GET /rest/auth` → `data.token` |
| 图书馆 / 房间 / 日期 | `GET /rest/v2/free/filters` |
| 房间余量 | `GET /rest/v2/room/stats2/{buildingId}` |
| 座位图 | `GET /rest/v2/room/layoutByDate/{roomId}/{date}` |
| 起止时间 | `GET /rest/v2/startTimesForSeat/{seatId}/{date}`、`/endTimesForSeat/{seatId}/{date}/{start}` |
| 预约 | `POST /rest/v2/freeBook`（`seat`、`date`、`startTime`、`endTime`） |
| 当前预约 | `GET /rest/v2/user/reservations` |
| 取消 | `POST /rest/v2/cancel/{id}` |
| 历史 | `GET /rest/v2/history/{page}/{count}` |

## 2. 改动范围

| 维度 | Ham | 本项目 |
| --- | --- | --- |
| 平台 | React Native / Web | 原生 Android（Kotlin + Jetpack Compose） |
| 导航 | 图书馆 Tab | 首页即预约入口 + 底部「预约 / 常用 / 设置」 |
| UI | RN 组件 | 全新 Material 3 设计（珞珈绿 + 樱粉），支持深色模式 |
| 存储 | RN 侧本地存储 | DataStore Preferences + kotlinx.serialization |
| 登录 | 账号密码 / CAS | WebView 打开官方登录页，手动验证码 / SSO，捕获 token |
| 数据源 | 真实接口 | `LibraryApi` 契约 + `WhuLibraryApi`（经典）/ `DemoLibraryApi`（演示） |
| 默认图书馆 | 无 | 新增，持久化并同步首页 |
| 默认楼层 | 无 | 新增，首页默认展示该楼层房间 |
| 常用座位 | 单一首选座位 | 新增收藏列表 + 首页一键预约 |

改动的边界很明确：**业务行为复用，界面与数据落地方式重写**。经典接口的字段解析、错误码、时间格式（分钟数）保持原样，因此换回旧版部署时不需要改业务层。

## 3. 新增功能的实现结构

### 3.1 默认图书馆 / 默认楼层

```
SettingsStore (DataStore)
  ├─ default_building / default_floor
  └─ UserSettings
        ↓
HomeViewModel.load()
  ├─ repo.catalog() 读缓存或 filters
  ├─ 校验默认值是否存在于目录（防止换馆后楼层失效）
  ├─ 首次进入自动落一个可用默认值
  └─ repo.roomStats(buildingId) → 首页楼层房间列表
        ↓
SettingsScreen：图书馆弹窗 / 楼层 chips → repo.updateDefaultTarget()
HomeScreen：切换图书馆 / 楼层同样写回默认值
```

关键点：首页切换会**直接更新默认值**，不需要再去设置页二次确认；设置页修改后返回首页，`HomeViewModel.refreshOnResume()` 检测默认目标变化并重新加载。

### 3.2 常用座位

```
SeatMapScreen 座位详情
  └─ 星标 → repo.addFavorite(FavoriteSeat)
        ↓ DataStore(JSON)
FavoritesScreen / HomeScreen 横向卡片
  └─ 一键预约 → QuickBookUseCase.book(favorite, date, fallbackEnabled)
```

`FavoriteSeat` 保存了座位 id、座位号、房间、图书馆、楼层、靠窗/电源标签，避免预约时再查一次目录。

### 3.3 一键预约与附近座位回退

`QuickBookUseCase` 的流程：

1. 计算时间段：默认时间段；当天则从“当前时间向上取整到半小时”开始。
2. 次日预约在 22:45 前直接提示（图书馆规则；演示模式不限制）。
3. 读取目标区域座位图。
4. 候选顺序：目标座位（空闲时）→ 同区域曼哈顿距离最近的空座。
5. 逐个尝试，每次间隔 350ms，最多 4 次；命中即返回，并标记是否使用了回退。
6. 全部失败返回最后一次错误；登录失效单独返回 `NotLoggedIn`。

回退开关关闭时只尝试目标座位，对应 Ham“首选座位失败就提示”的行为。

### 3.4 WebView 登录

```
HomeScreen「登录」/ SettingsScreen「登录」
        ↓
WebLoginScreen（WebView）
  ├─ 加载 {baseUrl}/seat/#/login
  ├─ 用户手动输入账号密码 + 图片验证码，或走统一身份认证
  ├─ onPageFinished / doUpdateVisitedHistory 注入轮询脚本
  ├─ 轮询 sessionStorage/localStorage 的 token（真实 key 为 jsq_p-token，兼容无前缀）
  ├─ JS Bridge: SeatBridge.onLogin(token, userInfo)
  ├─ 立即保存 token 并返回首页（不阻塞等待网络）
  └─ 首页加载时用 getUserInfo 补齐姓名/学号
        ↓
自动返回首页，顶部显示姓名，设置页显示「Web 登录」
```

设计取舍：

- **不碰密码**：账号密码、验证码、滑块、CAS 跳转都在官方页面完成。
- **不猜页面结构**：只读 token，再用官方 `getUserInfo` 校验并取用户信息。
- **可重登**：token 过期后清除会话，重新走网页登录即可。
- **兼容登录页改版**：登录页地址由设置的服务器地址拼接，改版只需改 URL。

### 3.5 演示数据源

`DemoLibraryApi` 与真实接口实现同一 `LibraryApi` 契约，内置总馆 / 工学分馆 / 信息科学分馆 / 医学分馆、楼层、房间与确定性占座数据，支持预约、取消、历史。用于无账号时的界面与流程验证，不影响真实接口适配。

## 4. 新版 `/jsq` 协议勘查（登录相关）

武大本部已将经典 `/rest/*` 全部 302 到 `https://seat.lib.whu.edu.cn/seat/#/login`，新前端 `jsq-pc` 使用 `/jsq` 前缀。实测结论：

- `GET /rest/auth`、`/rest/v2/free/filters` 均返回 `302 Location: /seat/#/login`，经典接口已停用。
- 新登录：`POST /jsq/static/public/auth/user`
  - `username` / `password` 使用 **AES-128-CBC / PKCS7 / Base64** 加密；
  - key 为固定字符串 `server_date_time`，iv 为 `client_date_time`（前端 `config.js` 可见）；
  - 请求体还需 `sysCaptchaRes: { captchaId, captchaText }`；
  - 缺验证码返回 `{"status":false,"code":500,"message":"验证码不能为空"}`。
- 图片验证码：`POST /jsq/static/public/cg/generateCaptcha/{username}` → `captchaId` + 图片 data URL。
- 认证后所有请求带 `token` header；失效返回 `{"code":20002,"message":"token认证无效"}`。
- 关键数据端点：
  - `POST /jsq/static/frontApi/res/buildingFloorDate`
  - `POST /jsq/static/frontApi/res/findRoomDuration/{venueId}/{date}`
    - 路径最后一段是日期（`yyyy-MM-dd`），`floorId` 在 body；
    - body 需带 `currentPage`、`pageSize`、`floorId`（字符串雪花号）、`beginMinute`、`endMinute`、`power`、`windows`、`roomType`、`sortField`、`sortType`；
    - 返回分页对象 `{ currentPage, pageSize, totalCount, pageList: [...] }`；
    - `pageList` 的每一项是房间：`id`、`name`、`floorId`、`seatTotal`、`seatFree`。
  - `POST /jsq/static/frontApi/res/querySeatLayout/{roomId}/{updV}`（返回带 `_updVersion_` 标记的 LZString 压缩字符串）
  - `POST /jsq/static/frontApi/make/freeBook/{seatId}/{date}/{startMinute}/{endMinute}?capToken=…`
  - `POST /jsq/static/frontApi/user/currentUseMake`
  - `POST /jsq/static/frontApi/make/cancel/{id}`
  - `POST /jsq/static/frontApi/user/getUserInfo`
- 公开系统配置：`POST /jsq/static/public/cg/getSysSet/PC`（预约开放时间、暂离/违约规则等，无需登录）。

因此登录采用 WebView 方案：把带验证码/SSO 的认证交给官方页面，App 只接收 `sessionStorage.token`，再用 `getUserInfo` 校验。这样即使登录接口再改，登录流程也不会失效。

> 注意：前端用 `sessionStorageProxy` 包了一层，真实 key 是 `jsq_p-token`（不是 `token`）。App 的轮询脚本同时兼容带前缀和不带前缀，避免登录成功后取不到凭证。

当前数据层有三套实现，共用一个 `LibraryApi` 契约：

- `JsqLibraryApi`：新版 `/jsq` 真实接口（Web 登录后默认使用）；
  - `buildingFloorDate` 解析图书馆 / 楼层 / 日期；
  - `findRoomDuration` 解析房间 `seatTotal` / `seatFree`；
  - `querySeatLayout` 用 LZString 解压 Fabric.js JSON，读取 `labeledImage.seat`，按 `left/top` 聚类成网格；
  - `freeSeatIdsDuration` 合并指定日期的空闲座位；
  - `freeBook` / `currentUseMake` / `cancel` / `history` 完成预约闭环；
  - 所有请求按前端逻辑附加 `X-request-id` / `X-request-date` / `X-hmac-request-key`（HMAC-SHA256，密钥由公开配置 `getSysSet/PC` 下发并 AES 解密）。
- `WhuLibraryApi`：Ham 经典 `/rest` 协议，兼容旧部署。
- `DemoLibraryApi`：离线演示数据，未登录时使用。

`LibraryRepository` 依据“演示模式 / 服务器地址 / Web 会话”选择实现，UI 与业务层不感知接口版本。新版座位图解析的关键是：`querySeatLayout` 返回 `LZStringBase64(JSON + "_updVersion_" + version)`，座位对象是 Fabric 的 `labeledImage`，座位字段在 `seat` 子对象里。

### 解析层 PC 单测

`app/src/test/java/.../JsqParserTest.kt` 用真实返回结构做纯 JVM 测试（不依赖模拟器/网络），覆盖：

- `buildingFloorDate`：标准字段、别名字段（`buildId/buildName/floorList`）、嵌套 `data`；
- `findRoomDuration`：`pageList` 分页、`seatTotal/seatFree`、`floorId` 归属、无余量字段降级、`seatCount/emptyCount` 模糊字段；

- 预约状态：`CHECK_IN` → `IN_USE`；
- 起止时间：`[[600,"10:00"]]` 分钟对；
- 请求体：`currentPage/pageSize/floorId` 等分页字段。

另有 3 个真实返回 fixture（目录、4F 房间、354 座位布局 + 状态）做整包解析：

## 5. 登录保持（静默续期）

- 新版 jsq 的 token 有效期较短（实测几十分钟），官方页面在 20003 时只会提示重新登录。
- 站点配置 `CASLOGIN=2`，登录页提供「统一身份认证登录」：走 `https://seat.lib.whu.edu.cn/rem/static/sso/login` → 武大统一身份认证 `cas.whu.edu.cn`（TGC 记住登录 Cookie）→ 带 `?token=票据` 回跳 → `POST /jsq/static/public/auth/cas/{ticket}` 换取新 token，全程可静默。
- App 实现：`CasSessionManager` 用隐藏 WebView 走 SSO 链路拿票据并换取新 token；`LibraryRepository.withSessionRetry` 在任意接口 20003 时自动静默续期并重试一次。
- 用户只需在登录页用「统一身份认证」成功登录一次（CAS Cookie 持久保存在 WebView CookieManager），之后关闭/重开 App 都会自动续期，无需重复登录。用「图书馆认证登录」则没有 CAS Cookie，掉线仍需手动登录。
- 注意：图书馆公告禁止高频调用接口，因此不做定时心跳，仅在请求失败时按需静默续期。

## 6. 预约前人机校验（滑块）

`systemInfo.mackCaptcha = 2`，预约接口必须带有效的 `capToken`，否则返回“验证码错误”。

- 预约流程：点预约 → 弹出 App 内原生卡片 → 卡片内嵌官方 TAC 滑块（只加载验证码区域，不显示登录页/站点 UI）→ 验证成功拿 `res.data.token` 作为 capToken → 调 `freeBook/...?capToken=...`。
- 为什么内嵌官方组件：TAC 的校验请求使用 CryptoJS/JSEncrypt 组合加密（`id + data + custom + ki`），并且依赖 `jsq_JSESSIONID` 会话；直接复刻容易出现服务端 500。内嵌官方组件能保证与网页端完全一致。
- 验证页是最小 HTML（不加载整站），按顺序引入 `crypto-js.min.js`、`jsencrypt.js`、`tac.min.js` 和官方 `app.css`，否则 TAC 初始化会因缺少 `CryptoJS` 直接失败、图片永远不出现。
- 外层标题、关闭、刷新按钮均为原生 Compose，视觉与 App 其他卡片一致。
- 用户取消或关闭弹窗时抛出“已取消安全验证，预约未提交”，不会产生预约。

## 6. 已知边界

- WebView 登录需要人工完成图片验证码，符合“用户手动验证”的要求，不做自动识别。
- token 由座位系统决定有效期，过期后需重新登录。
- 新版 `/jsq` 的字段解析按前端实现推断，并对常见字段名做了兼容；如学校后续改字段，解析层的容错与日志需要同步更新。
- 预约可能触发新版的人机校验（`capToken`），当前按空值提交；若系统要求滑块验证，会返回明确错误，需在官方页面完成。
- 本项目不是官方客户端，请遵守座位系统的使用规则，避免高频请求。
